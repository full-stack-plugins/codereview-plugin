# commit-review Specification

## Purpose
将语义审查结果绑定到实际准备提交的内容与已授权上下文，区分有效结果、跳过、部分失败和过期证据，为用户提供可追踪的风险建议，而不是凭模型结论宣称代码安全。
## Requirements
### Requirement: 精确提交内容
系统 MUST 审查确定的候选提交内容；普通提交使用暂存区，未暂存和未跟踪文件不得被悄悄纳入提交审查。审查过程 SHALL 保持原仓库 HEAD、分支、索引、工作区不变。无法准确确定候选内容的提交形式 MUST 报告不支持，要求分解操作或显式跳过可选审查，不得套用旧报告。

#### Scenario: 部分暂存
- **WHEN** 同一文件同时存在暂存和未暂存修改
- **THEN** 报告对应暂存版本，工作区中的额外修改不作为已审查的提交内容

#### Scenario: 首次提交
- **WHEN** 仓库尚无 HEAD 但存在暂存文件
- **THEN** 系统以空树为基线审查首次提交，且不在用户仓库创建提交

#### Scenario: 非标准提交
- **WHEN** 命令使用 amend、路径限定、仅提交选中文件或无法解析的复合 Shell
- **THEN** 系统不声称审查覆盖该操作，提供受支持的操作分解或跳过路径，不改写用户的 Git 语义

### Requirement: 报告与证据失效
报告 SHALL 包含仓库与 worktree 身份、基线、候选内容标识、授权范围、引擎版本、运行标识和上下文摘要。提交前 MUST 复核内容与基线；变化使报告过期，同逻辑任务可在有效授权内重新审查。

#### Scenario: 审查后继续修改
- **WHEN** 审查完成后暂存区或 HEAD 发生变化
- **THEN** 旧报告不能复用于新提交，系统返回需要重新审查或用户选择跳过的状态

### Requirement: 审查结果不等于门禁裁决
系统 SHALL 默认输出建议，不以发现问题为理由永久禁止提交。有问题时展示位置、严重性、证据、修复建议和覆盖局限，并允许用户选择修复后重审或保留风险继续。没有发现问题 MUST 表述为已审查范围内未发现问题，不得宣称无风险。

#### Scenario: 用户选择保留风险
- **WHEN** 审查发现问题而用户明确要求继续提交
- **THEN** 系统记录该决定并允许本插件的流程继续，不伪造审查通过或替其他插件豁免

### Requirement: 引擎异常不得伪装成功
系统 MUST 校验结构化报告，不能仅凭进程退出码或空问题列表判定完成。超时、缺失引擎、无凭据、无支持文件、部分失败、异常 JSON、未知状态和输出污染 SHALL 单独表示；用户可选择重试或跳过，不得陷入必须修好引擎才能提交的循环。

#### Scenario: 退出码正常但部分失败
- **WHEN** 引擎退出码为 0 且报告包含文件审查错误
- **THEN** 系统保留错误和已获得的问题，标记覆盖不完整，不输出无问题通过

#### Scenario: 全部文件被过滤
- **WHEN** 引擎跳过所有候选文件
- **THEN** 系统报告未完成有效审查及原因，不把空列表当作无问题

### Requirement: OCR 双执行模式
系统 SHALL 默认提供 Delegation Mode，通过 `ocr delegate preview` 和 `ocr delegate rule` 使用 OCR 的文件筛选与规则解析，由当前宿主智能体完成逐文件审查；系统 MAY 提供 OCR-managed Mode，通过 `ocr review` 让 OCR 配置的模型完成审查。系统 MUST 以能力探测选择可用命令，不把未知版本当作兼容，也不得因为 Delegation Mode 无需 OCR API Key 就跳过用户审查授权。

#### Scenario: 委托模式没有 OCR LLM 配置
- **WHEN** 用户授权 Delegation Mode 且 OCR 提供 delegate JSON 能力，但没有配置 OCR provider/API key
- **THEN** 系统生成结构化文件与规则计划，由宿主智能体审查，OCR 端不调用 LLM

#### Scenario: 委托覆盖不完整
- **WHEN** 宿主智能体提交的报告没有逐一说明 preview 中的可审查文件
- **THEN** 系统拒绝将报告记为完成，保留待审任务并指出缺失文件

#### Scenario: OCR 托管输出文件
- **WHEN** OCR 提供 `--output` 能力并选择 OCR-managed Mode
- **THEN** 系统使用本次运行的私有唯一结果文件读取 JSON，不依赖混有进度或遥测信息的 stdout，失败时不复用旧结果

### Requirement: 审查执行范围和隔离
系统 SHALL 只在授权后执行配置的引擎，将候选代码和必要上下文置于隔离临时目录，默认不运行项目脚本、Git Hooks 或模型建议命令。符号链接、子模块、冲突索引和快照规模超限 MUST 明确处理或拒绝，不能越界读取或静默漏审。

#### Scenario: 仓库路径越界
- **WHEN** 候选文件包含指向仓库外的符号链接或恶意路径
- **THEN** 系统不读取外部目标，返回不支持或明确的排除原因

#### Scenario: 运行失败与清理
- **WHEN** 引擎失败、被取消或输出不合法
- **THEN** 系统保留经过脱敏的失败证据，清理本次临时快照，不复用上次输出冒充当前结果
