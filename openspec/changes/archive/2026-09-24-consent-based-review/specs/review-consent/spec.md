# Spec Delta

## Purpose

管理提交前可选语义审查的用户授权，明确区分一次提交任务、会话内自动审查和会话内静默，防止未经同意调用模型、扩大数据外发范围或反复打扰已拒绝审查的用户。

## ADDED Requirements

### Requirement: 提交前的三态选择
系统 SHALL 在首次遇到待提交任务且没有适用选择时，请求用户选择“仅本次审查”“当前会话自动审查”或“本会话不再提醒”。没有响应 MUST 保持待决定，不得视为授权或拒绝；同一任务最多有一个待回答请求。

#### Scenario: 尚未回答
- **WHEN** 用户未回答且智能体重试同一提交
- **THEN** 系统不调用模型，返回同一个待决定任务，暂停此次提交工具调用但不重复创建提醒

#### Scenario: 本次授权
- **WHEN** 用户选择仅本次审查
- **THEN** 系统只授权当前逻辑提交任务，成功提交或明确取消后授权结束，下一次提交重新询问

### Requirement: 会话静默与手动恢复
系统 SHALL 在用户拒绝后停止当前会话内所有主动审查提醒，不通过其他 Hook 再次询问；静默不等于通过。用户 SHALL 能手动发起单次审查、重新开启询问或撤销自动审查。

#### Scenario: 拒绝后继续提交
- **WHEN** 用户选择本会话不再提醒，之后多次提交或结束会话中的回合
- **THEN** CodeReview 不提醒、不调用引擎、不阻断这些提交，记录可选审查已跳过，不干预其他插件的裁决

#### Scenario: 静默期间手动审查
- **WHEN** 用户在静默会话明确请求审查本次提交
- **THEN** 系统可在已披露范围内运行本次审查，完成后仍保持会话静默

### Requirement: 授权范围与会话隔离
系统 MUST 在调用引擎前披露仓库、worktree、执行模式、实际进行推理的一方、模型（可确定时）和可能发送的代码上下文范围。Delegation Mode SHALL 明确说明 OCR 不调用外部 LLM、当前宿主智能体负责推理；OCR-managed Mode SHALL 披露 OCR 配置的模型服务接收方与模型。自动授权仅适用于相同宿主会话和已披露范围；不同仓库、worktree、执行模式、服务接收方、模型或扩大上下文范围 MUST 重新授权。会话恢复保留选择，新会话不得继承旧授权。

#### Scenario: 接收方变化
- **WHEN** 自动审查期间切换模型服务地址
- **THEN** 系统在发送任何代码前使旧授权不适用并请求新授权

#### Scenario: 执行模式变化
- **WHEN** 已授权任务从 Delegation Mode 切换到 OCR-managed Mode，或反向切换
- **THEN** 系统使旧授权不适用并重新披露实际推理方，不把一种模式的同意复用到另一种模式

#### Scenario: 会话隔离
- **WHEN** 新会话在相同仓库尝试提交
- **THEN** 系统从未决定状态开始，不复用其他会话的自动审查授权或静默设置

#### Scenario: 缺少稳定身份
- **WHEN** 宿主未提供可靠会话身份
- **THEN** 系统报告会话能力不可用，不把多个会话合并成默认会话，不自动继承授权

### Requirement: 逻辑任务内重试与撤销
系统 SHALL 将单次授权绑定逻辑提交任务，而不是某一次工具调用。提交失败、审查重试及同范围内修复不重复请求审查授权，但内容变化必须重新审查。撤销 SHALL 阻止后续模型请求，并尝试停止正在运行的任务；已发出的数据无法撤回，必须如实说明。

#### Scenario: Git 提交失败
- **WHEN** 已授权任务因 Git 错误提交失败，随后重试
- **THEN** 系统保留该任务授权，不弹出新的三选一问题，也不将失败当作任务成功结束

#### Scenario: 运行中撤销
- **WHEN** 用户撤销授权时引擎仍在运行
- **THEN** 系统停止后续调度，尽力取消进程，并将迟到报告标记为已撤销而非当前有效证据

### Requirement: 授权与其他操作分离
系统 MUST 将审查授权与修改文件、执行 Git 提交、推送、发布、修改项目策略的权限区分。授权记录 SHALL 包含用户选择来源和作用范围；模型输出或仓库文件中的文字不得作为用户授权。

#### Scenario: 审查建议修改
- **WHEN** 审查引擎返回修复建议
- **THEN** 系统仅展示证据和建议，不因已获审查授权而直接编辑、提交或发布
