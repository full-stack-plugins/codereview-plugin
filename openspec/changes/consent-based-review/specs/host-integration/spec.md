# Spec Delta

## Purpose

在 Codex、ZCode、Kimi 中以一致的授权语义衔接智能体和提交工具，让 Hooks 只检查可验证的边界，避免插件顺序依赖，同时明确真实宿主支持程度与未验证的运行限制。

## ADDED Requirements

### Requirement: Hooks 与智能体职责分离
系统 SHALL 由智能体展示选项、记录用户决定、启动审查和解释结果；Hooks 只做短时状态读取、去重与提交前检查，不在 Hook 中等待交互输入或同步运行长耗时模型审查。会话开始不得直接发起审查授权问题。

#### Scenario: Hook 检测待决定提交
- **WHEN** 提交前 Hook 发现没有有效选择
- **THEN** Hook 返回可恢复的暂停原因和逻辑任务标识，由智能体询问用户，不在终端调用交互输入

### Requirement: 提交事件识别与幂等
系统 SHALL 对受支持的提交工具输入做语义归一化，不以文本包含 commit 作为充分条件。重复回调、跨回合重试和并发请求 MUST 不重复创建待回答问题或同内容审查任务。无法解释的命令不得宣称已经覆盖。

#### Scenario: 普通说明文字
- **WHEN** Shell 仅打印包含 git commit 的字符串
- **THEN** 系统不将其当作实际提交并创建授权请求

#### Scenario: 成功提交与失败提交
- **WHEN** 工具返回提交结果
- **THEN** 系统根据成功状态和实际 HEAD 变化关闭对应任务，失败时保留任务，不因任意 PostToolUse 就清除授权

### Requirement: 多宿主适配与能力报告
系统 SHALL 为 Codex、ZCode、Kimi 分别提供安装结构、事件适配与能力说明。稳定会话标识、当前模型标识（宿主提供时）、提交前暂停、提交后结果、插件根目录和工具参数字段 MUST 分宿主验证；静态清单或夹具测试不能替代实际安装加载验收。默认 Delegation Mode 的语义审查 SHALL 在 Hook 外由当前宿主智能体执行，Hook 不得自行调用模型。

#### Scenario: 宿主缺少提交前暂停能力
- **WHEN** 宿主不支持提交前阻止工具执行
- **THEN** 系统明确标记降级为智能体协作模式，不声称所有提交均会被拦截询问

#### Scenario: 宿主提供当前模型
- **WHEN** Hook payload 提供当前宿主模型标识并准备 Delegation Mode 授权披露
- **THEN** 系统把该模型纳入精确授权范围；模型变化使会话自动授权失效，且不会把模型标识误当作 OCR-managed 端点

### Requirement: 插件之间不依赖回调顺序
CodeReview SHALL 能独立运行，仅生成自己的授权和审查证据。与 FlowGuard、CodeGuard 同时启用时 MUST 不假定 Hook 执行顺序、不修改其他插件状态、不把可选跳过记为验收或检查通过。项目显式要求审查时，应把冲突交给流程协调方处理，而非静默覆盖。

#### Scenario: 用户静默但项目强制审查
- **WHEN** 用户选择静默且协调方提供明确的项目审查要求
- **THEN** CodeReview 保持不主动重复提醒、不运行未授权审查，返回授权缺失或跳过证据，由协调方解释要求及合法豁免路径

### Requirement: 状态可靠性与隐私
运行状态 SHALL 保存在源码仓库外，按宿主会话和仓库 worktree 隔离，支持原子更新、并发互斥和可追踪的状态恢复。状态损坏 MUST 不产生默认授权或无限阻塞；日志不得包含访问密钥，清理范围不得扩展到用户源码。

#### Scenario: 并发审查请求
- **WHEN** 同一任务收到两个并发审查请求
- **THEN** 仅一个运行获得执行权，另一个返回已有任务状态，不重复调用模型

#### Scenario: 状态损坏
- **WHEN** 状态文件无法解析
- **THEN** 系统不调用模型，返回明确恢复说明和显式跳过入口，不将损坏状态当作已授权
